# Project Governance

Kiv is currently maintained by a small core team. We follow a lightweight governance model inspired by Rust.

## Decision Process

- **Bug fixes & minor improvements**: Approved by any maintainer.
- **New language features or breaking changes**:  
  Require an accepted RFC and consensus from the core team.
- **Disagreements**: The project lead has final say (BDFL-style), but will seek broad consensus first.

## RFC Process

All significant changes must go through the RFC process:
1. Fork the repo
2. Add your RFC as `docs/design/rfcs/XXXX-title.md`
3. Submit a PR
4. Discuss and iterate
5. Merge if accepted

This ensures design clarity and long-term consistency.
